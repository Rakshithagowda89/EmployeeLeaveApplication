# Employee Leave Management System

## Project Overview

The Employee Leave Management System is a RESTful web application developed using Spring Boot. It allows employees to apply for leave and provides APIs to manage leave applications, search employee records, filter and sort leave details, and approve or reject leave requests.

The project demonstrates CRUD operations, Bean Validation, Lombok, Java Stream API, custom exceptions, and global exception handling.

## Technologies Used

- Java 17
- Spring Boot
- Spring Web
- Lombok
- Jakarta Bean Validation
- Maven
- Postman
- Eclipse / Spring Tools for Eclipse

## Dependencies

### Spring Web
Used to create REST APIs using annotations such as `@RestController`, `@GetMapping`, `@PostMapping`, `@PutMapping`, `@DeleteMapping`, and `@PatchMapping`.

### Lombok
Used to reduce boilerplate code. The `@Data` annotation generates getters, setters, `toString()`, `equals()`, and `hashCode()`. The `@NoArgsConstructor` annotation generates a no-argument constructor.

### Validation
Used to validate request data with annotations such as `@NotBlank`, `@NotNull`, `@Min`, `@Max`, `@Email`, `@Pattern`, and `@Valid`.

## Model Fields

The `EmployeeLeave` model contains the following fields:

| Field | Description |
|---|---|
| leaveId | Unique leave application ID generated by the service |
| employeeId | Employee identification number |
| employeeName | Name of the employee |
| leaveType | Type of leave: Casual, Sick, Earned, or Unpaid |
| numberOfDays | Number of leave days requested |
| reason | Reason for applying for leave |
| startDate | First day of leave |
| endDate | Last day of leave |
| email | Employee's email address |
| status | Leave status: Pending, Approved, or Rejected |

## Features

### 1. CRUD Operations
- Create a leave application.
- Retrieve all leave applications.
- Retrieve a leave application by ID.
- Update an existing leave application.
- Delete a leave application.

### 2. Search Operations
- Partial matching using `contains()`.
- Exact matching using `equalsIgnoreCase()`.

### 3. Filtering
- Filter by leave type.
- Filter by leave status.
- Filter by number of leave days.
- Filter by date range.

### 4. Sorting
- Sort employee names alphabetically.
- Sort leave days in ascending order.
- Sort leave days in descending order.

### 5. Custom Operations
- Count all leave applications.
- Count leave applications by status.
- Approve a leave application.
- Reject a leave application.

### 6. Validation
- Employee ID must be positive.
- Employee name is required and must contain valid characters.
- Leave type must be Casual, Sick, Earned, or Unpaid.
- Leave days must be between 1 and 365.
- Reason must contain between 5 and 250 characters.
- Start and end dates are required and cannot be in the past.
- End date cannot be before start date.
- Email must be valid.
- Status must be Pending, Approved, or Rejected.

### 7. Exception Handling
- `LeaveNotFoundException` handles missing leave records.
- `GlobalExceptionHandler` handles validation errors, business validation errors, missing records, and unexpected exceptions.
- HTTP 400 is returned for invalid requests.
- HTTP 404 is returned when a leave application is not found.
- HTTP 500 is returned for unexpected server errors.

## Setup and Installation

### Prerequisites
- Java 17 or later
- Maven
- Eclipse or Spring Tools for Eclipse
- Postman

### Steps to Run

1. Clone or download the project.
2. Import the project into Spring Tools for Eclipse as an existing Maven project.
3. Make sure the Spring Web, Lombok, and Validation dependencies are included in `pom.xml`.
4. Update the Maven project.
5. Ensure Lombok support is installed in Eclipse if Lombok annotations are not recognized.
6. Run `EmployeeLeaveApplication.java` as a Spring Boot application.
7. Open Postman and send requests to `http://localhost:8080/leaves`.

## API Endpoints

Base URL: `http://localhost:8080/leaves`

### CRUD APIs

| Method | Endpoint | Description |
|---|---|---|
| POST | `/leaves` | Create a leave application |
| GET | `/leaves` | Retrieve all leave applications |
| GET | `/leaves/{id}` | Retrieve a leave application by ID |
| PUT | `/leaves/{id}` | Update a leave application |
| DELETE | `/leaves/{id}` | Delete a leave application |

### Search APIs

| Method | Endpoint | Description |
|---|---|---|
| GET | `/leaves/search?name=art` | Search employee names using partial matching |
| GET | `/leaves/search/exact?name=Artha%20Gowda` | Search employee names using exact matching |

### Filter APIs

| Method | Endpoint | Description |
|---|---|---|
| GET | `/leaves/filter/type?type=Sick` | Filter by leave type |
| GET | `/leaves/filter/status?status=Pending` | Filter by leave status |
| GET | `/leaves/filter/days?days=2` | Filter by number of leave days |
| GET | `/leaves/filter/date?from=2026-11-01&to=2026-11-30` | Filter leave applications by date range |

### Sorting APIs

| Method | Endpoint | Description |
|---|---|---|
| GET | `/leaves/sort/name` | Sort by employee name A–Z |
| GET | `/leaves/sort/days/asc` | Sort leave days in ascending order |
| GET | `/leaves/sort/days/desc` | Sort leave days in descending order |

### Count APIs

| Method | Endpoint | Description |
|---|---|---|
| GET | `/leaves/count` | Count all leave applications |
| GET | `/leaves/count/status?status=Approved` | Count leave applications by status |

### Approval APIs

| Method | Endpoint | Description |
|---|---|---|
| PATCH | `/leaves/1/approve` | Approve leave application with ID 1 |
| PATCH | `/leaves/1/reject` | Reject leave application with ID 1 |

## Sample Request: Create Leave Application

**Method:** POST

**URL:** `http://localhost:8080/leaves`

**Body → raw → JSON**

```json
{
  "employeeId": 101,
  "employeeName": "Artha Gowda",
  "leaveType": "Casual",
  "numberOfDays": 2,
  "reason": "Family function",
  "startDate": "2026-11-10",
  "endDate": "2026-11-11",
  "email": "artha@example.com",
  "status": "Pending"
}
```

The application generates the `leaveId` automatically.

## Sample Request: Update Leave Application

**Method:** PUT

**URL:** `http://localhost:8080/leaves/1`

**Body → raw → JSON**

```json
{
  "employeeId": 101,
  "employeeName": "Artha Gowda",
  "leaveType": "Sick",
  "numberOfDays": 3,
  "reason": "Medical rest required",
  "startDate": "2026-11-10",
  "endDate": "2026-11-12",
  "email": "artha@example.com",
  "status": "Pending"
}
```

This updates the existing leave application with ID 1, provided it exists and the request passes validation.

## Limitations

This project uses an in-memory `ArrayList` to store leave applications. Data is lost when the application restarts. It does not currently use a database or implement authentication, employee-specific leave balances, working-day calculations, or role-based approval permissions.

## Future Enhancements

## Conclusion

The Employee Leave Management System demonstrates how to develop a RESTful application using Spring Boot, Spring Web, Lombok, and Validation. It provides CRUD operations, search, filtering, sorting, approval workflows, and centralized exception handling.
